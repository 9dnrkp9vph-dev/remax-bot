# חתימות: webhook ישיר מפיירברי + חיסון כפילויות בין-מקורות (13/08/2026)

## הבעיה
שורות החתימה מגיעות היום בצינור עקיף: אוטומציית פיירברי → Apps Script → גיליון → (sync) → Supabase,
ובנוסף טאב "חתימות" ידני בגיליון (הדבקות ייצוא מה-CRM) משמש בסיס היסטורי. התוצאה: תלות בגוגל האיטי,
וכפילויות כשאותה החתמה מגיעה משני מקורות עם הבדלי איות/תאריך — התסמין שאייל דיווח 13/08:
"ממוצע הנכסים שנצפו · 2 נכסים" על החתמה של נכס אחד (avg_n סופר את אותו נכס פעמיים).

## הפתרון (מתכון החשבוניות — a7579d0)
1. **`POST /v2/api/signatures/ingest`** (effie_v2): פיירברי שולח ישירות לאפליקציה.
   - אימות: שדה `token` בגוף (קיים כבר באוטומציה) או header `X-Sign-Key`, מושווה
     hmac.compare_digest למשתנה סביבה `SIGN_INGEST_KEY`; ריק = endpoint כבוי (403).
   - קלט סובלני: שדות אנגלית (event_id, deal_type, agent, client_name, address, city,
     commission_pct, notes, phone, date/received_at) או עברית מקבילה; שדות חסרים = ''.
   - תאריך: `date`/`received_at` בפורמט ISO או DD/MM/YYYY [HH:MM]; לא-פריס/חסר → עכשיו (שעון ישראל).
   - כתיבה: upsert ל-`signatures` (הטבלה הקיימת) עם `source_key='fb:'+event_id`
     (בלי event_id → 'fbh:'+sha1 של השדות המהותיים). on_conflict=(office_id,source_key)
     merge — הטריגר "נוצרה או עודכנה" מעדכן שורה קיימת, retry לא מכפיל.
   - `raw` jsonb במבנה getRaw_ (המפתחות שהאפליקציה קוראת), `received_at` עמודת date לסינון.
2. **חיסון כפילויות ב-`get_signings`** (app.py): הדדופ המדויק (`_seen_exact`) מוחלף במפתח יציב:
   (סוכן canon, לקוח canon, יום, `_deal_label`, עוגן-כתובת). עוגן-כתובת = מהכתובת המנורמלת
   (`_sign_addr_key`) עד וכולל המספר הראשון — "קרן היסוד 112, קרית ביאליק" ו"קרן היסוד 112"
   מתמפים לאותו עוגן; אין מספר → המפתח המלא. העדפה: שורה עם `commission_pct` (קישור מסמך חתום)
   גוברת על שורה בלי; אחרת הראשונה נשארת.
   - נשמר בכוונה: זוג מוכר+בלעדיות (label שונה) = 2 שורות; שני נכסים שונים לאותו לקוח באותו
     יום (עוגן שונה) = 2 שורות; ריבוי נכסים בטופס אחד = שורה אחת ממילא.
3. **צד פיירברי (אייל):** שכפול האוטומציה הקיימת, החלפת URL ל-
   `https://remax-bot.onrender.com/v2/api/signatures/ingest`, רשומת בדיקה, ואז כיבוי
   אוטומציית ה-Apps Script הישנה (rollback = הדלקה מחדש).
4. **Env (אייל):** `SIGN_INGEST_KEY` ב-Render = ערך ה-token שכבר בגוף האוטומציה.
