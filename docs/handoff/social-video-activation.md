## 1. Supabase — SQL (פעם אחת)

(יוצר את `social_videos` ואת `social_links`, עם RLS בלי policies — שרת בלבד).

## 2. Render — Environment
| משתנה | ערך | הערה |
|---|---|---|
| `FAL_KEY` | המפתח מ-fal.ai | כבר הוגדר (02/11) |
| `SOCIAL_VIDEO_AUTO` | לא להגדיר עדיין | `1` רק אחרי בדיקה ידנית מוצלחת |
| `FAL_VIDEO_MODEL` | לא חובה | ברירת מחדל: `fal-ai/kling-video/v2.5-turbo/pro/image-to-video` |
| `SOCIAL_VIDEO_APPROVER` | לא חובה | ברירת מחדל: הטלפון של אייל (DEV_PHONES) |
| `WA_TPL_VIDEO` | רק אחרי אישור התבנית (סעיף 4) | עד אז — הודעת טקסט עם קישור לדף אישור |

`SOCIAL_MODE=publish` ו-`META_TOKEN` כבר מוגדרים (מהפוסטים).

## 3. דפלוי ובדיקה ראשונה
1. push + Manual Deploy (החבילה החדשה `imageio-ffmpeg` מותקנת אוטומטית).
2. בכלי המפתח (`/v2/dev`) → כרטיס "סרטונים לרשתות" — צריך להופיע "fal: מחובר".
3. בנכסים → נכס של המשרד → **"צור סרטון סטורי + ריל"** (זהב). אחרי 2–4 דקות:
   - בוואטסאפ מגיע הסרטון לאייל ולסוכן עם "פרסם" / "דלג" (אם פתוח חלון 24 שעות — כפתורים; אחרת קישור לדף אישור).
   - "פרסם" → עולה לסטורי + ריל באינסטגרם ולסטורי + ריל בעמוד הפייסבוק.
4. לבדוק בעמוד ובאינסטגרם את ארבעת המקומות. אם ערוץ נכשל — בכרטיס הנכס "נסה שוב את מה שנכשל".

## 4. תבנית וואטסאפ `video_review` (לא חובה — משפרת את החוויה מחוץ לחלון 24 שעות)
ב-360dialog → Templates → New:
- **שם:** `video_review` · **קטגוריה:** UTILITY · **שפה:** Hebrew
- **Header:** Video (דוגמה: כל MP4 קצר)
- **Body:** `{{1}}` — דוגמה: `סרטון סטורי + ריל מוכן — 5 חדרים למכירה, גבעת הרקפות · 2,090,000 ₪`
- **Buttons:** Quick reply ×2 — `פרסם`, `דלג`
אחרי שמטא מאשרת: `WA_TPL_VIDEO=video_review` ב-Render.

## 5. מוזיקה
כרגע: פד רקע עדין שנוצר אוטומטית. להחלפה במוזיקה אמיתית — לשים 5 קבצי `.mp3` חופשיים לשימוש מסחרי
(למשל Pixabay Music) בתיקייה `assets/music/` ולרשום אותם ב-`assets/music/SOURCES.md`.

## 6. אוטומטי
אחרי כמה סרטונים ידניים טובים: `SOCIAL_VIDEO_AUTO=1` ב-Render → כל נכס משרד חדש (עד 3 ביום) מקבל סרטון
שנשלח לאישור. לפני זה — לבדוק ב-Render שגודל השרת לפחות 2GB זיכרון.
